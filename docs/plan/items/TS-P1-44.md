## Problem

`from xml` ended in `yield return document`, handing a CLR `XDocument` to the
pipeline. Every other format in the family converts: `from json` yields a record,
`from csv` and `from tsv` a list of records, `from toml` a record.

Two consequences. The display engine reflected over the document and printed
`NodeType`, `BaseUri`, `Parent` and `<cycle>` markers instead of the data. And
`to xml \| from xml` was the only pair in the format family that did not round-trip.

## Acceptance

- [x] `from xml` yields shell data, so `to xml \| from xml` round-trips like the other formats
- [x] the `XDocument` stays reachable behind `--raw` rather than being removed
- [x] the existing test that pinned the raw document keeps passing, now pinning the escape hatch

## Notes

Handing over the document *was* a deliberate choice — it is how a caller reaches the
XML API for namespaces and node-level navigation — so what changed is which of the two
is the default, not whether the capability exists.

Implementation is in `src/Tosh.Runtime/Formats/XmlDataFormat.cs` and
`src/Tosh.Runtime/XmlValueConverter.cs`; tests in `XmlConversionTests` and
`StructuredDataCommandTests`.
