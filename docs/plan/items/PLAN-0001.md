## Problem

Twenty-odd documents, last touched between April and now, with no way to tell from
reading one whether it is current. `ARCHITECTURE.md` was written carefully and still
drifted within four months — it described `Tosh.Core` as present for four months after
the commit that deleted it.

The rule that makes this tractable: **a document is either generated, live, or history
— and history should say so in its first line.**

The sequencing matters more than the work. Rewriting an architecture document before
the architecture changes means rewriting it twice, so this item covers *dating and
labelling* now, and defers the rewrites to after the split.

## Acceptance

- [ ] `BENCHMARKS.md` (April, 100 lines), `TUI_ARCHITECTURE.md` and `TOME.md` carry an as-of date or are re-measured
- [ ] `COMPILED_TOSH.md` (1,023 lines) carries a header saying it describes a frozen component
- [ ] `BRACE_DISAMBIGUATION_RFC`, `LINE_EDITOR_RFC` and `SELF_HOSTING_RFC` marked decided-and-implemented, or moved to an `rfc/` directory
- [ ] `CONFIGURATION`, `EDITOR_SUPPORT`, `TSSP`, `CLR_ABI_v1` and `RUNTIME_NAMESPACES` read once against the code, then corrected or date-stamped
- [ ] `BACKLOG.md` resolved against the plan — live epics kept as design documents with items filed against them, the rest archived
- [ ] `Tosh.Dap` (550 lines, referenced by nothing) labelled dormant-by-intent rather than left to look abandoned
- [ ] Whatever survives has an owner and a trigger recorded — "update when the solution layout changes"
- [ ] `ARCHITECTURE.md` rewritten **after** `TOAST-0006`, around the new boundary

## Notes

The last two boxes are the ones that matter. Everything else is a one-time tidy; an
owner and a trigger is what stops the same drift recurring, and the `ARCHITECTURE.md`
rewrite is the one piece of real writing here.

`docs/diagnostic-codes.md` and the command reference are generated — leave them alone.
