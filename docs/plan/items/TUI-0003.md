## Problem

`HelpBrowserScreen` and `ConfigBrowserScreen` are 6,800 lines that build their own
sidebars, detail panes, search rows, footers, dialogs and hit rectangles out of the 285
lines of primitives in `TuiRenderHelpers`. They are not duplicated code — a clone audit
measured 2% literal and 7% structural overlap, because both already call
`RenderDualPaneContent`, `RenderSearchRow` and `RenderFooterLine`. What they duplicate
is the *composition*: each one wires state objects to primitives by hand, because there
is no level above the primitives to work at.

Until they are ported, the widget layer is a claim. Porting them is the test: two apps
that are genuinely different — one navigates a catalogue, the other edits a config tree
with validation, staging and eight kinds of editor — should come out shorter and share
their furniture.

## Acceptance

- [ ] Both browsers build a widget tree instead of concatenating lines
- [ ] The sidebar, detail pane, search box and footer are shared widgets, not per-screen rendering
- [ ] The confirmation dialog draws as an overlay rather than by splicing lines into the screen's own output
- [ ] The `_lastListRect`-style hit rectangles are gone, replaced by hit testing against the arrangement
- [ ] The CLR explorer's type pages and the config editors survive the move unchanged in output
- [ ] `TuiBrowserGoldenTests` passes without re-recording, or every diff is read and explained

## Notes

The golden masters recorded in `e5d1681` exist for this item. Ten scripted sessions
snapshot every frame, including the CLR type page and the config value editors, so a
port that changes output says so. That is the whole reason they were written before
anything moved.

Expect the config browser to be the harder of the two: its editors mutate, its detail
pane renders live previews of the user's theme and prompt, and the prompt preview is
deliberately scrubbed from the snapshots because it embeds the working directory, git
state and the last command's duration.

`TuiCustomScreen` should come out of this too. Once widgets compose, the 753-line
interpreter over a closed enum has nothing left to interpret.
