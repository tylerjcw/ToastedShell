> **Withdrawn 2026-09-25** under `TOAST-ARCH-01`: Tōast has no compiler ([COMPILER_DECOMMISSIONING_PLAN.md](../../COMPILER_DECOMMISSIONING_PLAN.md)). There is no compilation for the TUI surface to survive.

## Problem

The TUI is meant to be usable from the shell, from Tōast scripts, and eventually from
compiled Tōast programs. The first two are exercised; the third is assumed.

One piece of evidence says the assumption is reasonable: handlers are typed as
`IShellCallable`, and both engines implement it — the interpreter through
`Tosh.Language.Bridge.FunctionCommand`, the compiler through
`ToshHost.FunctionReferenceValue`. A `&handler` should therefore mean the same thing in
both. Nothing tests it.

Other parts are less certain and nobody has looked:

- Widget trees built from `{| |}` record literals arrive as `ExpandoObject`. What a
  compiled program produces for the same syntax is not established here.
- The tick invoker builds a `CommandContext` and drains an async enumerable
  synchronously. Whether that is available and sane in a compiled program is unknown.
- `Tosh.Tui` now references `Tosh.Runtime` for theme configuration, which pulls the
  shell's config system into anything that draws.

## Acceptance

- [ ] A compiled Tōast program builds and runs a TUI screen, as a test
- [ ] `&handler` resolves and invokes identically under both engines
- [ ] The record-literal tree form works, or the difference is documented and a second form provided
- [ ] The public surface avoids interpreter-only types
- [ ] The theme dependency is either confirmed acceptable or inverted behind an interface

## Notes

Compiled ToastScript is an experiment and this item is not a request to advance it. It
is a guard: the point is to notice *now* if a design choice in the TUI would be
impossible to compile later, while changing it is cheap.

The theme coupling is the known soft spot. `Tosh.Tui` took a reference on
`Tosh.Runtime` in `ddf1ddc` because the render helpers take `ToshTuiThemeConfig`,
`ToshTextStyleConfig` and `ToshTableBoxStyle` directly. The alternative — declare a
theme interface in `Tosh.Tui` and have the config types implement it — keeps `Tosh.Tui`
a leaf. It was not done because those types appear in eight files' signatures.
