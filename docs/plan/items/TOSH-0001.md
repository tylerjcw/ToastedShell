## Problem

An argument that contains quotes rather than beginning with them keeps its quote
characters when it reaches an external program.

```tosh
/usr/bin/echo --opt="x*y" plain="q"
```

```
TōSh:  --opt="x*y" plain="q"
POSIX: --opt=x*y plain=q
```

The quotes are doing their job as far as suppressing glob expansion goes — `x*y` is
not expanded — but they are then handed to the callee as literal characters.

Found writing `scripts/plan.tosh`. Its `orphans` subcommand ran

```
/usr/bin/grep -roh --include="*.cs" ... src tests scripts
```

and reported **zero** matches where bash reports 854, because grep was searching for
files literally named `"*.cs"`, quotes included. Nothing errored; the command
succeeded and found nothing, which is the worst shape a defect of this kind can take.
It cost a full debugging pass to find, and the script now writes `--include=*.cs`
unquoted with a comment pointing here.

This is a portability trap rather than an inconvenience: `--opt="value"` is ordinary
in shell scripts, so anything pasted or ported from `sh` is silently wrong, and only
where the callee happens to tolerate the quotes does it appear to work.

## Acceptance

- [x] `--opt="x"` reaches an external command as `--opt=x`
- [x] `--opt='x'` behaves likewise
- [x] quoting still suppresses glob expansion and word splitting — `--opt="x*y"` is not expanded, and `--opt="a b"` stays one argument
- [x] an embedded quote that is meant literally still has a spelling, and it is documented — quote the whole word (`"--opt=\"x\""`) or use the other quote character (`'"'`); both already worked and are unaffected
- [x] behaviour is pinned for a leading-quote argument (`"--opt=x"`)
- [x] a negative control: 6 of 19 tests fail with the call sites reverted

## Resolution — 2026-08-17

**Two halves, and only fixing both makes the acceptance true.**

*Quote removal* is `ShellWordQuoting.StripBalancedQuotes`, applied where a bareword argument
becomes a value. The rule is POSIX word expansion's — quote characters are removed wherever
they are balanced within a single word, so `--opt="a"b"c"` is `--opt=abc`. An **unbalanced**
quote leaves the word exactly as written: `5"` is inches, and silently deleting the mark
would be a second silent-wrong-answer in the code built to remove one.

*Word splitting* needed the lexer. `--opt="a b"` was **two** arguments — `--opt="a` and
`b"` — because the bareword scanner broke on whitespace regardless of quote state. It now
consumes a quoted run inline, the way glob alternation already did.

**The lexer change is guarded by a same-line lookahead**, and that guard is the whole reason
it is safe. A quote only opens a run when its partner is on the same line, so `don't stop`
and `5" pipe` keep their marks and still split at whitespace. Without it those words would
swallow the rest of the line — a worse defect than the one being fixed, landing on words
people type at a prompt.

**Glob suppression survives because the check moved to the syntax.** Stripping happens at
evaluation, so by the time expansion runs, `x"*"y` and `x*y` are the same string; only the
written form still knows which one asked for expansion. The glob step now reads the raw
bareword text rather than the evaluated value.

### The audit found one, and it was this item's own workaround

`scripts/plan.tosh` had written `--include=*.cs` unquoted with a comment pointing here. Both
spellings are now correct, and it is **left unquoted deliberately**: the script runs with
whichever `tosh` is on `PATH`, and the quoted form needs the fix to be published first.
Verified both ways — 174 citations under the installed shell and the freshly built one. The
comment no longer claims TōSh is broken.

## Notes

Decide deliberately what `--opt="a"b"c"` means before fixing, and write it down — the
answer is unobvious and every shell has picked a slightly different one. The
narrow reading is that quote characters are removed wherever they are balanced within
a single word, which is what POSIX word expansion does.

Worth auditing the repository's own `.tosh` scripts for the same pattern once fixed;
this one was found by accident, and `scripts/` is the place it would hide.
