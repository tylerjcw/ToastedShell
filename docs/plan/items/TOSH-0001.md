## Problem

An argument that contains quotes rather than beginning with them keeps its quote
characters when it reaches an external program.

```tosh
/usr/bin/echo --opt="x*y" plain="q"
```

```
TōSh:  --opt="x*y" plain="q"
POSIX: --opt=x*y plain=q
```

The quotes are doing their job as far as suppressing glob expansion goes — `x*y` is
not expanded — but they are then handed to the callee as literal characters.

Found writing `scripts/plan.tosh`. Its `orphans` subcommand ran

```
/usr/bin/grep -roh --include="*.cs" ... src tests scripts
```

and reported **zero** matches where bash reports 854, because grep was searching for
files literally named `"*.cs"`, quotes included. Nothing errored; the command
succeeded and found nothing, which is the worst shape a defect of this kind can take.
It cost a full debugging pass to find, and the script now writes `--include=*.cs`
unquoted with a comment pointing here.

This is a portability trap rather than an inconvenience: `--opt="value"` is ordinary
in shell scripts, so anything pasted or ported from `sh` is silently wrong, and only
where the callee happens to tolerate the quotes does it appear to work.

## Acceptance

- [ ] `--opt="x"` reaches an external command as `--opt=x`
- [ ] `--opt='x'` behaves likewise
- [ ] quoting still suppresses glob expansion and word splitting — `--opt="x*y"` is not expanded, and `--opt="a b"` stays one argument
- [ ] an embedded quote that is meant literally still has a spelling, and it is documented
- [ ] behaviour is pinned for a leading-quote argument (`"--opt=x"`), which already works, so the fix cannot regress it
- [ ] a negative control: reverting the fix fails the new tests

## Notes

Decide deliberately what `--opt="a"b"c"` means before fixing, and write it down — the
answer is unobvious and every shell has picked a slightly different one. The
narrow reading is that quote characters are removed wherever they are balanced within
a single word, which is what POSIX word expansion does.

Worth auditing the repository's own `.tosh` scripts for the same pattern once fixed;
this one was found by accident, and `scripts/` is the place it would hide.
