> Status as filed: Proposed — filed 2026-08-13. **Superseded by `TOAST-0018` on 2026-08-17**, which carries the same ground with the eight concerns enumerated and measured. Withdrawn rather than expanded: new work does not go into the `TS-P*` system.

## Problem

ToastScript-owned core types and their conformance corpus

## Acceptance

Specify `str`, `int`, `dec`, `list`, `dict`, `date`, `duration` and `regex` in ToastScript terms rather than by reference to the BCL, with one conformance corpus both targets must pass. This is the load-bearing wall of the native design: it is what lets .NET be demoted from *the* object model to *a* foreign world alongside the C ABI. Cheap to begin now — the types can keep their BCL implementations while the specification is written — and expensive to retrofit later, because every script and doc written against `System.String` semantics is a lock-in.
