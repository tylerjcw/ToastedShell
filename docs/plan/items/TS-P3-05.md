> Status as filed: Proposed

## Problem

Uniform thrown-value protocol

## Acceptance

Wrap thrown non-exception values so `catch (e)` always exposes `.Message` and a kind discriminator; today `throw "boom"` followed by `$e.Message` is a runtime error.

## Withdrawn — 2026-09-20, superseded by `TOAST-0031`

The acceptance asks to "wrap thrown non-exception values so `catch (e)` always exposes
`.Message` and a kind discriminator". Both halves have since been decided the other way, on
purpose, and the specification states it.

**Wrapping is what `§Errors and catch` forbids.** Its first paragraph is headed *"Anything can
be thrown, and arrives unchanged"*, with `throw "a plain string"` binding that string. A
wrapper would break that promise, and with it `echo $e`, `$e.Length`, equality against the
thrown value, and `throw $e` re-raising what was caught.

**The kind discriminator exists**, and is three-way rather than one flag.
[`TOAST-0031`](TOAST-0031.md) built it. Measured 2026-09-20:

| Thrown | `is Failure` | `is Error` | `is Diagnostic` | `.Message` |
|---|---|---|---|---|
| `"boom"` | false | false | false | — |
| `new Error("x")` | true | true | false | `x` |
| `1 / 0` | true | false | true | `Division by zero.` |
| `class B(m) extends A($m)`, `A extends Error` | true | true | false | `deep` |

That a bare thrown string has no `.Message` is the design, not the gap: the specification says
a merely-thrown value is *none* of the three, "which is what keeps `Failure` meaning 'something
went wrong' rather than 'something was thrown'". Giving it a `.Message` would be asserting that
a string is a failure.

## A probe that lied, recorded because it nearly closed the wrong thing

The first measurement of the subclass row read `is Failure` true, `is Error` **false** — an
apparent contradiction of the specification's "at any depth of inheritance". It was written as:

```tosh
class AppError extends Error { }
try { throw new AppError("a") } catch ($e) { ... }
```

`AppError` declares no constructor taking an argument, so `new AppError("a")` raises "No
constructor matched class 'AppError' with 1 argument(s)" — *inside the `try`*. The catch bound
that diagnostic, and a diagnostic is correctly `is Failure` and not `is Error`. The probe had
caught its own malformed construction and presented it as the subject under test.

A `try` block that constructs the value it is testing will swallow construction failures and
hand them to the handler as though they were the thrown value. Construct outside the `try`, or
assert on what was caught before drawing a conclusion from it.
