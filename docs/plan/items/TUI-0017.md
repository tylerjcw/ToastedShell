## Problem

`ls | tui pick` shows a column of names. `ls | tui table` shows nothing, because there is
no table. In a shell where every pipeline stage carries objects with properties, the
control that displays objects with properties is the one most obviously missing — and the
shell already has a table renderer for its *non*-interactive output, so a reader sees
columns everywhere except inside the TUI.

Rich's `Table` is the reference: column widths from content with per-column overrides,
alignment, headers and footers, row styles, and a decision about what to do when it does
not fit. Ratatui's is leaner and adds row selection, which is the part a picker needs.

## Acceptance

- [x] `TuiTable` takes rows of objects and columns named by property, as `TuiList` takes items
- [x] Column widths are measured from content, with fixed, star and auto per column
- [x] A row can be selected and activated, so `tui pick --table` is the same screen
- [x] Cells are styled per column, and a cell can be styled per value
- [x] It scrolls itself vertically, like `TuiList` and `TuiLines`
- [x] It scrolls horizontally as well, for more columns than fit
- [x] The header stays put while the rows move
- [x] `ls | tui table` works from a script with no scaffolding
- [x] Borders are a property: none, a rule under the header, or the full grid the shell prints

## Notes

The shell's own `ObjectFormatter` already decides which properties of an object are worth
showing and how wide they should be. Reusing that decision is what keeps `ls | tui table`
and `ls` showing the same columns; re-deriving it here would be a second opinion nobody
asked for.

## What landed

All of it. Left and right move along the columns, which is the only thing those keys could
mean in a grid and the only way to reach a column that does not fit. Whole columns are
dropped off the left rather than cells being shifted sideways, so every column on screen is
intact and its header still sits above it — half a column is not a reading of anything.
`AllColumnsFit` says whether there is anything off-screen to move to.

Columns are derived from the first row when nobody says what they are, and *how* they are
derived is the part that mattered. Reflection over a `FileInfo` gives forty-nine columns;
`ls` shows four. So `TuiTable.ColumnSource` is a hook the host installs, and the shell
fills it from the display engine it already uses — the same columns, the same alignment,
and the same cell text, because `DisplayEngine.FormatTableCellValue` is now public. A file
reads `133 kB` and `63 minutes ago` inside the TUI exactly as it does at the prompt.

Column widths use `TuiLength`, so a table's columns are divided by the rules a screen's
panes already use, bounds included — which is what `TUI-0019` was worth doing first for.

`Borders` is `None`, `Header` or `All`. None by default, because a table inside a
`TuiBorder` already has an outline and a second one around it is a double rule; `All` is
what the shell prints at the prompt. `TuiBorderGlyphs` grew the five junctions a grid needs
and defaults them from the line characters, so an ASCII border stays drawable without
listing more punctuation.
