## Problem

`ls | tui pick` shows a column of names. `ls | tui table` shows nothing, because there is
no table. In a shell where every pipeline stage carries objects with properties, the
control that displays objects with properties is the one most obviously missing — and the
shell already has a table renderer for its *non*-interactive output, so a reader sees
columns everywhere except inside the TUI.

Rich's `Table` is the reference: column widths from content with per-column overrides,
alignment, headers and footers, row styles, and a decision about what to do when it does
not fit. Ratatui's is leaner and adds row selection, which is the part a picker needs.

## Acceptance

- [ ] `TuiTable` takes rows of objects and columns named by property, as `TuiList` takes items
- [ ] Column widths are measured from content, with fixed, star and auto per column
- [ ] A row can be selected and activated, so `tui pick --table` is the same screen
- [ ] Cells are styled per column, and a cell can be styled per value
- [ ] It scrolls itself, vertically and horizontally, like `TuiList` and `TuiLines`
- [ ] The header stays put while the rows move
- [ ] `ls | tui table` works from a script with no scaffolding

## Notes

The shell's own `ObjectFormatter` already decides which properties of an object are worth
showing and how wide they should be. Reusing that decision is what keeps `ls | tui table`
and `ls` showing the same columns; re-deriving it here would be a second opinion nobody
asked for.
