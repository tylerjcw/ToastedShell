## Problem

An external program's stdout becomes one `ShellTextLine` per line, and every consumer is handed
those lines — including another program and a file. `ExecuteWithPipesAsync` decodes stdout as
UTF-8 and splits it (`ConsumePlainStdoutAsync`); the next program's stdin is written
`WriteLineAsync(ExternalTextSerializer.Serialize(item))` (`PumpStandardInputAsync`); `out>` writes
every yielded value as a text line (`EvaluatePipelineWithRedirectionAsync`); `in<` feeds the first
stage the file's lines (`ReadLinesAsync`).

Measured 2026-09-25 on the Debug build:

- `/usr/bin/cat bin.dat | /usr/bin/sha256sum`: 100,000 random bytes arrive as 181,127, because
  every invalid UTF-8 sequence is replaced by U+FFFD and re-encoded as three bytes.
- `/usr/bin/cat bin.dat out> out.bin` writes the same 181,127 corrupted bytes, and
  `/usr/bin/cat bin.dat | /usr/bin/gzip -c out> out.gz` writes an archive that decompresses to
  nothing.
- A file without a trailing newline gains one (19 bytes become 20).
- 50 MB through `/usr/bin/cat big.txt | /usr/bin/wc -l` spends 3.4 s piping, against 44 ms in bash.

A second defect lives in the same code. `var x = (a | b)` passes `outputIsCaptured` to every stage,
and at a terminal `DetermineSpawnMode` answers `Hybrid` for each of them: stdout piped, stdin and
stderr inherited. That is right for the first stage and wrong for the rest —
`var x = (/usr/bin/printf "hello\n" | /usr/bin/tr a-z A-Z)` at a TTY captured what was typed at the
keyboard, because `tr` read the terminal instead of `printf`.

## Acceptance

- [x] adjacent external programs pass bytes directly: `cat | sha256sum` preserves every byte
- [x] `out>` to a single file writes an external program's bytes unchanged, and `cat | gzip -c out> f.gz` round-trips
- [x] `in<` feeds an external program the file's bytes: `gzip -dc in< f.gz` round-trips
- [x] no trailing newline is added to output that had none
- [x] a consumer that exits early closes the producer's pipe, so the producer ends instead of hanging
  — whether it then dies of `SIGPIPE` or reports `EPIPE` is [`TOSH-0014`](TOSH-0014.md)
- [x] only the first stage of a captured pipeline at a terminal runs hybrid; `var x = (printf … | tr …)` returns `HELLO`
- [x] TōSh stages still receive text lines, TSSP producers still yield records, and the existing external-process tests pass
- [x] background pipelines (`… &`) get the same: bytes to a single `out>` file and from `in<`, no
  byte-order mark, and no hang when a reader exits early

## Notes

The design, and why it is a hand-off rather than a marker on the stream, is in
[`POC_IMPROVEMENT_PLAN.md`](../../POC_IMPROVEMENT_PLAN.md#p01-binary-safe-external-io--tosh-0012).
In short: the engine creates a `RawByteHandoff` between adjacent command stages and between the last
stage and a single `out>` file, bound to the two resolved command instances. The consumer offers a
destination before it pulls; a producer whose stdout turned out to be plain claims it, copies bytes
into it and yields nothing. A marker on the producer's enumerable cannot work: each stage reaches
the next through the engine's own `ExecuteCommandSyntaxAsync` iterator, so the next stage never
sees the producer's enumerable.

## Outcome

Measured 2026-09-25 on the Debug build, after the change:

| Case | Before | After |
|---|---|---|
| `/usr/bin/cat bin.dat \| /usr/bin/sha256sum`, 100,000 random bytes | 181,127 bytes arrived | the file's own hash |
| `/usr/bin/cat bin.dat out> out.bin` | 181,127 bytes | identical to the input |
| `… \| /usr/bin/gzip -c out> f.gz`, then `gunzip` | empty | identical to the input |
| `/usr/bin/gzip -dc in< f.gz \| /usr/bin/sha256sum` | — | the original's hash |
| a 19-byte file without a final newline, `out>` | 20 bytes | 19 bytes |
| 50 MB, `/usr/bin/cat \| /usr/bin/wc -l` | 3.4 s of piping | about 0.1–0.2 s over the shell's 0.5 s startup |
| `var x = (/usr/bin/printf "hello\n" \| /usr/bin/tr a-z A-Z)` under a pty | read the keyboard | `HELLO` |
| `/usr/bin/yes \| /usr/bin/head -1 &` | "running" forever | completes in 0.5 s |
| background `out>` of `hi\n` | `EF BB BF` + `hi\n` | `hi\n` |
| `sh -c "printf ab; sleep 3" \| …`: when the next program sees `ab` | after 3.45 s, at exit | at once |

The last row is the protocol sniff: it waited for as many bytes as the TSSP magic is long before
deciding a program's output was plain, and now decides at the first byte that differs.

Tests: `ExternalByteStreamTests` and two pty cases in `TtyCaptureTests`. Each fix was negated in
turn and the tests aimed at it failed; the early-exit test times out without the pipe being
closed.

## What the design became

The hand-off is bound to the `CommandContext` the engine built for each stage rather than to the
resolved command, as first planned: a registered command is one object shared by every stage that
names it, whereas a context is per stage, and a copy made with `with` is a different object that
therefore cannot claim.

## Known limits

- A TōSh function or script that runs a program is not a byte path: in `func f() { cat x }` then
  `f | sha256sum`, the function yields lines. Forwarding the hand-off into a function's last
  statement would close this.
- Several `out>` targets, and the buffered plans (`o+e>`, one file named twice), still write text.
- The last stage of a pipeline at the terminal still has its output displayed as lines.
- The builtins (`cat`, `head`, …) are text commands; `cat file | gzip` runs the builtin.
