## Problem

An external program's stdout becomes one `ShellTextLine` per line, and every consumer is handed
those lines — including another program and a file. `ExecuteWithPipesAsync` decodes stdout as
UTF-8 and splits it (`ConsumePlainStdoutAsync`); the next program's stdin is written
`WriteLineAsync(ExternalTextSerializer.Serialize(item))` (`PumpStandardInputAsync`); `out>` writes
every yielded value as a text line (`EvaluatePipelineWithRedirectionAsync`); `in<` feeds the first
stage the file's lines (`ReadLinesAsync`).

Measured 2026-09-25 on the Debug build:

- `/usr/bin/cat bin.dat | /usr/bin/sha256sum`: 100,000 random bytes arrive as 181,127, because
  every invalid UTF-8 sequence is replaced by U+FFFD and re-encoded as three bytes.
- `/usr/bin/cat bin.dat out> out.bin` writes the same 181,127 corrupted bytes, and
  `/usr/bin/cat bin.dat | /usr/bin/gzip -c out> out.gz` writes an archive that decompresses to
  nothing.
- A file without a trailing newline gains one (19 bytes become 20).
- 50 MB through `/usr/bin/cat big.txt | /usr/bin/wc -l` spends 3.4 s piping, against 44 ms in bash.

A second defect lives in the same code. `var x = (a | b)` passes `outputIsCaptured` to every stage,
and at a terminal `DetermineSpawnMode` answers `Hybrid` for each of them: stdout piped, stdin and
stderr inherited. That is right for the first stage and wrong for the rest —
`var x = (/usr/bin/printf "hello\n" | /usr/bin/tr a-z A-Z)` at a TTY captured what was typed at the
keyboard, because `tr` read the terminal instead of `printf`.

## Acceptance

- [ ] adjacent external programs pass bytes directly: `cat | sha256sum` preserves every byte
- [ ] `out>` to a single file writes an external program's bytes unchanged, and `cat | gzip -c out> f.gz` round-trips
- [ ] `in<` feeds an external program the file's bytes: `gzip -dc in< f.gz` round-trips
- [ ] no trailing newline is added to output that had none
- [ ] a consumer that exits early ends the producer the way `SIGPIPE` would, without hanging
- [ ] only the first stage of a captured pipeline at a terminal runs hybrid; `var x = (printf … | tr …)` returns `HELLO`
- [ ] TōSh stages still receive text lines, TSSP producers still yield records, and the existing external-process tests pass

## Notes

The design, and why it is a hand-off rather than a marker on the stream, is in
[`POC_IMPROVEMENT_PLAN.md`](../../POC_IMPROVEMENT_PLAN.md#p01-binary-safe-external-io--tosh-0012).
In short: the engine creates a `RawByteHandoff` between adjacent command stages and between the last
stage and a single `out>` file, bound to the two resolved command instances. The consumer offers a
destination before it pulls; a producer whose stdout turned out to be plain claims it, copies bytes
into it and yields nothing. A marker on the producer's enumerable cannot work: each stage reaches
the next through the engine's own `ExecuteCommandSyntaxAsync` iterator, so the next stage never
sees the producer's enumerable.
