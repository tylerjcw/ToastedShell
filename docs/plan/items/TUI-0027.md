## Problem

```tosh
var lines = ["alpha", "beta", "gamma"]
func Log() => $lines
```

Invoked through `ToshEngine.ExecuteToListAsync` in a test, `Log` produces **one** value: a
`System.Object[]` of three. Invoked by the same code inside the real `tosh` binary running
the same script from a file, it produces **three** values, one per element.

That was found by accident. `TUI-0008` fixed a pull binding that kept only the last value a
function produced; the fix was verified in a pty, and the unit test written to pin it passed
identically before and after, because under the test engine there was only ever one value to
keep. The test had to be rewritten against a hand-written `IShellCallable` that yields three
values, which pins the invoker but says nothing about what a real function does.

Whichever behaviour is right, they cannot both be. And the consequence is worse than the
inconsistency: a test asserting how a script behaves is asserting how it behaves *under the
test engine*, and the two have now been shown to differ on something as ordinary as a
function returning a list.

## Acceptance

- [ ] Establish which is intended: does a function returning a collection spread into the pipeline or yield one value
- [ ] The two hosts agree, and a test pins the agreement
- [ ] Find what differs — engine construction, `IsInteractiveSession`, the callable bridge, or the statement path
- [ ] Audit what else the difference could have hidden: anything asserted through `ExecuteToListAsync` about a function's output
- [ ] Document the answer where a script author would look for it

## Notes

Spreading is the shell-shaped answer and matches how a pipeline reads — `$files | each`
should see files, not one array. Yielding the collection whole is the function-shaped
answer and matches `var x = F()`, which does hand back the array. It is possible both are
right and the difference is between calling a function and putting it in a pipeline, in
which case the bug is that the two hosts disagree about which context a binding's
invocation is.

Not TUI work, despite the id. Filed here because this is where it surfaced and the TUI is
what it broke.
