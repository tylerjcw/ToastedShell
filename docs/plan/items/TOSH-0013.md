## Problem

Builtins receive `CommandContext.Arguments` as evaluated `object?` values and find their options by
comparing `ToString()` with the option spellings — `HeadCommand.ParseArguments` is typical, and 55
files in the standard library do it. By the time a command sees its arguments, the engine has
discarded whether each one was written as a literal word or produced by a variable, a
subexpression, an interpolation or a glob.

Measured 2026-09-25:

```tosh
var name = "-r"
rm $name victim      # deleted victim/ recursively; the file named -r is untouched
var f = "-n"
head $f              # "Missing required argument: count."
```

Any value starting with a dash does this: a filename from `ls` or a glob, user input, a loop
variable. For a destructive command it is data loss.

## Acceptance

- [x] the engine records, for every argument it passes to a command, whether it came from a literal unquoted word
- [x] `rm` accepts options only from literal words; a computed `-r` is an operand
- [x] `mv`, `cp`, `chmod`, `chown` and `kill` likewise
- [x] a quoted literal (`rm "-r"`) is an operand, and `--` ends option parsing
- [x] glob results are operands: a file named `-rf` matched by `*` never becomes an option
- [x] the other files that match options by string are converted, or filed as a follow-up — `ln`
  and `xargs` converted; the rest filed as [`TOSH-0015`](TOSH-0015.md)

## Notes

External programs are out of scope: their argv is theirs to interpret, exactly as in bash. A lint
that suggests `--` when a value from a variable starting with `-` reaches a program is listed under
P2 in [`POC_IMPROVEMENT_PLAN.md`](../../POC_IMPROVEMENT_PLAN.md).

## Outcome

Measured 2026-09-26 on the Debug build:

| Case | Before | After |
|---|---|---|
| `var name = "-r"; rm $name victim` | `victim/` removed recursively; the file `-r` kept | the file `-r` removed; `victim` refused as a directory |
| `ls \| get Name \| xargs rm`, with a file called `-r` | `victim/` removed recursively | the same as above |
| `var r = "-R"; chmod 700 $r dir` | `dir` changed recursively | `dir` and the file `-R` changed, nothing below `dir` |
| `var m = "-w"; chmod $m file` | `-w` read as an option; the mode missing | the write bits removed |
| `kill -1`, or `kill $pid` holding -1 | every process the user owns killed | `-1 is not a process id.` |
| `signal TERM -1`, `signal TERM 0` | kill(2) on every process, or on TōSh's own group | refused |

`ArgumentProvenanceTests` covers each command, the forms a value can take (variable,
subexpression, interpolation, quoted string, splat, `|>`, glob), `--`, a command-wrapper
function, `invoke` and `xargs`. With word detection and the guards removed, 15 of its tests
fail; the other six check what must keep working either way.

## What the design became

- `CommandArgumentList` (`Toast.Runtime`) is the argument list itself, with a flag per argument.
  A command-wrapper function forwards its caller's list object, so provenance travels with it:
  after `func rmf => rm -rf`, `rmf -v x` keeps `-v` an option and `rmf $name` keeps `$name` a
  value. `CommandArguments.Slice` keeps it for `invoke`.
- `CommandContext.MayBeOption(i)` answers **no** for a list the engine did not build. A lost option
  is an error message; a value taken for an option can be a recursive delete.
- `ParsedCommandArguments.Parse(CommandContext)` is the provenance-aware parser; the list overload
  is unchanged for code that parses lists of its own.
- `xargs` re-parses the command line it builds, so a line of input is now always quoted, and only
  a word written to `xargs` itself may stay bare.

## Found on the way

- **`kill -1` killed every process the user owned.** `kill` reads no options, so `-1` is a target.
  On Linux, `Process.GetProcessById(-1)` tests existence with kill(-1, 0), which succeeds, and
  `Process.Kill` then sends kill(-1, SIGKILL); 0 does the same to TōSh's own process group. This
  was reproduced three times by accident, in a container running as root, and it took the
  container down each time. `kill` and `ProcessSignalSender` now refuse process ids of zero or
  less, and the tests use a value the same check refuses but that is harmless without it.
- **`signal` passed pids straight to kill(2)**, with the same consequence for -1 and 0.
- **`ln -f`** removes an existing destination, a directory recursively; it is converted with the
  six.

## Known limits

- Script files that declare `--flags` bind them from values (`ParseScriptArgumentValues`).
- The data formats (`to json --compact`, …) parse the arguments their command hands them as a list.
- Anything that reaches a builtin through a list the engine did not build gets no options at all —
  the safe side, but a behaviour change if something relied on it.
