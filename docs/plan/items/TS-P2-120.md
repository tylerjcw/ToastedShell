> Status as filed: Open

## Problem

**A nullable annotation on a built-in type alias will not parse in a `var` declaration.** `var x: int? = null` and `var x: string? = null` both fail with `tosh.bind.unknown_command` — *"Command 'var' is not a registered builtin or function declared in this source"* — a message that never mentions the annotation and points at column 1. The boundary is specific and is what makes it look like a parser special-case rather than a missing feature: `var x: Nonexistent? = null` parses fine and reaches the runtime annotation check, and `func f(a: int?)` works in parameter position. So the form is understood everywhere except a `var` declaration naming a built-in alias. Found while writing the `TS-P2-119` corpus; reproduces identically on a build of `HEAD`, so it is not related to that work.

## Acceptance

Find where a `var` declaration's annotation is parsed and why a known type alias followed by `?` diverges from an unknown name followed by `?` — the likely cause is the `?` being taken as the ternary operator once the preceding token resolves as a type. A corpus should cover `var` and `const` declarations for a built-in alias, a user class, an unknown name, and the parameter and return positions that already work, plus the diagnostic naming the annotation rather than the statement keyword.
