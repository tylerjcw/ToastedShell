## Problem

```tosh
var answer = tui confirm "Deploy now?"
writeline $"ANSWER={$answer}"
```

prints `ANSWER=TuiConfirmRequest`. The dialog never appears, and the variable holds
the request object instead of the user's answer.

The cause is the dispatch route. A full-screen subcommand does not run a screen; it
yields a request — `TuiConfirmRequest`, `TuiRunRequest` — which is intercepted further
down by `BufferingDisplaySink` and `StreamingTableSink`, run there, and replaced by its
outcome. A value assigned to a variable never reaches a display sink, so nothing
intercepts it and the request itself is what gets stored.

It works in the two shapes that happen to end at a sink:

```tosh
$screen | tui run                       # value flows to the sink
var answer = tui confirm "..." --cli    # inline prompt, returns a value directly
```

So the behaviour depends on where the value goes, which is not something a script
author can be expected to reason about — and the failure is silent. Nothing warns; a
screen simply does not appear and a variable holds an object nobody asked for.

Verified against the installed binary as well as the working tree, so it predates the
current TUI work.

## Acceptance

- [ ] `var x = tui confirm "..."` shows the dialog and binds the answer
- [ ] The same for `pick`, `filter`, `input`, `file` and `run`
- [ ] A request that reaches a variable, a function argument or a pipeline stage is run rather than stored
- [ ] `--cli` keeps returning its value directly, as it does now
- [ ] A request object that somehow escapes unrun is diagnosed rather than silently rendered as a type name

## Notes

Three shapes to weigh:

1. **Run at the command.** The subcommand runs the screen itself and yields the outcome.
   Simplest to reason about; needs the command to reach the terminal host, which is why
   it was not done this way — `Tosh.Stdlib` has no host.
2. **Run on materialisation.** Anything that converts a pipeline value to a stored value
   runs a pending request first. Keeps the current separation but puts TUI awareness in
   the assignment path.
3. **A lazy value that runs on first use.** Most flexible and the hardest to explain
   when it runs.

This matters more than its priority suggests, because it is the shape a script author
reaches for first: ask a question, keep the answer. `examples/reactor-block.tosh` works
around it with `--cli` without saying why.
