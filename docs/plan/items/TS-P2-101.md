## Problem

**Class and member doc comments never reach `help`.** A `##` block on a class parses into `ClassDefinitionStatementSyntax.DocComment` and is indexed for LSP hover, but `ToshClassDefinition` has no `DocComment` field, so nothing carries it to runtime. Measured: `help Color` on a fully documented class returns only the synthesised `ToSh type Color.`, while `help add` on a documented function returns description, per-argument text and examples. The same gap covers class properties and methods, interfaces, enums, records, modules and type aliases; `trait` is worse still, being absent from the LSP declaration index entirely. A library documented to the house standard is therefore discoverable in the editor and invisible in the shell.

## Acceptance

`help <Type>` and `help <Type>.<member>` return the parsed doc comment for classes, their properties and their methods, matching what functions already return. Traits appear in the LSP declaration index. A corpus asserts on summary, remarks and example text for a documented class, one of its properties, one of its methods, and a documented trait. **The parse side was already complete** — `ClassDefinitionStatementSyntax.DocComment`, `ClassPropertyMemberSyntax.DocComment`, and a method's wrapped `FunctionDefinitionStatementSyntax` all carry it — so nothing needed parsing work; the comment simply stopped at the runtime definition. `IShellTypeDescriptor` gains a **defaulted** `ShellDocumentation` (null), so a CLR-backed descriptor is not made to declare it has no ToastScript comment, and the five ToastScript definitions — class, record, struct, enum, interface, plus trait — store and surface theirs. `CreateShellTypeTopic` prefers the author's summary over the synthesised line. **All five kinds were done together on purpose**: each dropped the comment at the same place, so repairing one would have left the surface inconsistent in a way a single-kind test could not see. Three controls: an undocumented type still gets the synthesised description (an empty help entry is worse than a generic one), only `@summary` is promoted rather than the whole block, and documented *functions* — the reference behaviour — still work. The test probe had to be corrected on the way: `help` yields a topic object the CLI renders, so capturing stdout measured the renderer and did so inconsistently — a class printed while a struct produced nothing, which read as a missing fix rather than a mis-aimed probe. 8 tests; reverting only the catalog fails 6.

## Remaining

- [ ] **Remaining: `help <Type>.<member>`.** It does not resolve today for any type — `help K.P` answers "was not found" — so property and method documentation needs a help *resolution path that does not exist*, which is a feature rather than the plumbing this item turned out to be. Interfaces, enums, records and modules are done; `trait`'s absence from the LSP declaration index is also still open.
