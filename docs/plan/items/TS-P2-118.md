> Status as filed: Open — fixed 2026-08-17

## Problem

**Calling a callable held in a property warns `member_not_found`, then works.** `$c.Handler(7)` where `Handler` holds a function reference reports `⚠ tosh.type.member_not_found — Method 'Handler' was not found on type 'C'` and then returns 107. The runtime is right and the type checker is wrong, which is the worst pairing: the code works, so the warning is noise, and noise is what teaches people to stop reading warnings — the same reasoning as `TS-P2-09`. The `$this.Handler(...)` form inside a method does *not* warn, because `TS-P2-93` taught that path about callable properties; external access through an instance was not covered. Found while auditing the user's `Gl.tosh` and `Gtk.tosh`, whose remarks still described the whole shape as impossible.

## Acceptance

Teach the member-resolution check that a property whose value is callable is invocable, in whatever the shared place is — the fix should not be a second copy of the `TS-P2-93` rule, since the point is that one rule now lives in two paths. A corpus should cover the instance form, the `$this` form that already works, a property holding a lambda as well as a `&` reference, and a control that a genuinely missing member still warns.

## Resolution — 2026-08-17

`CheckUserMethodCall` looked only at *methods*. It now asks the same
`UserTypeMembers.TryGetProperty` lookup the member-access check uses, and a declared
property of that name suppresses the warning — so the rule is read from one place rather
than restated, which is what the acceptance asked for.

**Whether the property's *value* is callable cannot be known there.** The checker holds
annotation *names*, not declarations — `CheckUserMemberAccess` records exactly that two
methods below — and the shape in this item, `prop Handler = &addTen`, has no annotation at
all. So a declared property suppresses the warning outright. That trades a warning nobody
was getting, for calling a non-callable property, against one nobody wanted. Given the item
is about noise teaching people to stop reading warnings, that is the right way round.

A real method with the wrong arguments is still checked, and a genuinely absent member still
warns; both are pinned, because "stop warning" would have removed the check rather than
corrected it.

5 tests; 2 fail with the checker reverted, and the three that pass either way are the
controls.
