## Problem

[`TOSH-0013`](TOSH-0013.md) made the engine record which arguments were written as unquoted
words and converted the commands that destroy data — `rm`, `mv`, `cp`, `chmod`, `chown`,
`kill`, `ln` — plus `xargs`. The files below still find options by comparing argument values
with option spellings, through `ParsedCommandArguments.Parse(IReadOnlyList)` or by hand, so a
value that starts with a dash is still read as an option there: `var n = "-n"; head $n` fails with
"Missing required argument: count."

A search of them for deletion and force options found none (`ln -f` was the one, and is
converted), which is why they were not done with the destructive commands. The inventory was taken
on 2026-09-26 by searching for either form; `tee -a` is the nearest to harm, and a misread `-a`
there appends where it would have truncated.

## Acceptance

- [ ] each command below reads options only where `CommandContext.MayBeOption` allows —
  `ParsedCommandArguments.Parse(context)` for the common case — or is recorded here as having
  a reason not to
- [ ] commands that slice their arguments before parsing (`TuiCommand`, `to`/`from` handing
  arguments to a data format) keep the record, through `CommandArgumentList.Slice`
- [ ] script files that declare `--flags` bind them only from words (`ParseScriptArgumentValues`)

## Notes

The shape of each change is the one `TOSH-0013` used: replace `Parse(context.Arguments)` with
`Parse(context)`, or give a hand-written parser `context.MayBeOption(index)` beside each option
comparison, and add a case to `ArgumentProvenanceTests` showing a computed value is an operand.
