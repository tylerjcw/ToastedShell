## Problem

Every width calculation in the TUI goes through one function:

```csharp
public static int GetVisibleLength(string text)
{
    ArgumentNullException.ThrowIfNull(text);
    return text.Contains('\x1B') ? StripAnsi(text).Length : text.Length;
}
```

`.Length` is UTF-16 code units. That is the right answer for ASCII and wrong for
everything else a terminal renders:

| Text | Columns | `.Length` |
|---|---|---|
| `日本語` | 6 | 3 |
| `😀` | 2 | 2 |
| `👩‍💻` | 2 | 5 |
| `é` as `e` + U+0301 | 1 | 2 |

Borders, padding, column alignment, clipping and the ellipsis all consume this number,
so a single CJK filename, an emoji in a commit message or a decomposed accent shifts a
pane's right-hand border and every line below it. A process list or a file picker
reaches this on ordinary input, not on a contrived case.

## Acceptance

- [x] Width is measured in grapheme clusters, not code units or runes
- [x] East Asian Wide and Fullwidth count as two columns
- [x] Combining marks and zero-width joiners count as zero
- [x] Clipping never splits a grapheme cluster, and never leaves a half-drawn wide character
- [x] A wide character that does not fit in the remaining column is replaced rather than overflowing — **dropped**, not replaced; see below
- [x] Tests cover CJK, emoji, ZWJ sequences, combining marks and the clipping boundary

## Notes

Cheaper to fix once `TUI-0001` lands. With string frames the answer is needed wherever
text is concatenated; with a cell buffer a cluster occupies one or two cells at the
point it is written, and every consumer is right by construction.

`ClipPlain` also has a performance defect worth fixing in the same pass: it appends one
character at a time and recomputes the visible length of the whole accumulated string
each iteration, which is quadratic per line.

.NET has `StringInfo`/`TextElementEnumerator` for cluster segmentation. It has no East
Asian width table, so that part is a table to embed and keep current with Unicode
releases.

## Closed — 2026-09-20

Two halves, done at different times and only the second of them tonight.

**The TUI half** was already finished, under `TUI-0012`. `TuiTextMeasure` walks grapheme
clusters, counts East Asian Wide and Fullwidth as two, treats combining marks and
zero-width joiners as nothing, and truncates to a column budget without splitting a cluster.
`TextMeasureTests` covers CJK, an emoji, a ZWJ family emoji, both spellings of `é`, the
emoji presentation selector, and the clipping boundary.

**The shell half was not**, and that was the worse state of the two: the correct measurement
lived in `Tosh.Tui`, a project *above* the shell renderers, so nothing below could reach it.
`StyledText.GetVisibleLength` went on returning UTF-16 code units, and every caller padding
to a width took that answer — the table sink, the prompt renderer, `DisplayEngine`, the help
renderers, inline tables. A `ls` in a directory with CJK filenames drew a broken box:

```
 19 cols  ╭───┬─────────┬───╮
 22 cols  │ 0 │ 日本語     │ 1 │     right border pushed out by three
 19 cols  │ 1 │ abc     │ 2 │
```

`TextMeasure` moved down to `Toast.Runtime` beside `StyledText`, and twenty-six call sites
became correct at once. Four of them were wrong a second way the measurement alone does not
fix — a column budget used as a character index, `plain[..width - 1]` — so CJK overflowed by
up to double and an emoji lost half its surrogate pair. `WrapPlainLine` did the same with
`line.AsSpan(i, budget)`. Fixing only the measurement made that *worse*: the truncator
began correctly eliding a line the wrapper had incorrectly over-filled.

### The fifth criterion reads differently than it was written

It asked for a wide character that does not fit to be **replaced**. It is **dropped**, and
deliberately: "half a character is not something a cell grid can represent, and a terminal
asked to draw one corrupts the row" (`TuiBuffer.DrawText`). The column goes unused rather
than filled. `Truncate("日本語", 5)` is `"日本"` — the third would straddle the limit, so it
is not drawn at all. What the criterion was for, not overflowing, holds.

`ShellTextWidthTests` pins the shell half: that `GetVisibleLength` counts columns, that it
agrees with what the TUI draws with, that a clipped cell never exceeds its budget or splits a
character, and that a padded cell occupies exactly its width.
