## Problem

Single spurious failures appeared in **3 of 8 consecutive full-suite runs on an
unchanged tree**, in two unrelated areas:

- `TtyCaptureTests.An_interpolation_hole_does_not_yet_capture`, which shells out to
  `git` inside a PTY;
- `GenericClassTests.Generic_class_user_interface_constraint_accepts_implementing_class`.

Unrelated areas failing intermittently points at the harness rather than at either
test — most likely parallel execution sharing something it should not.

A suite that fails a third of the time on an unchanged tree cannot be used as evidence,
which is the real cost: every genuine regression now has to be re-run to be believed,
and a real failure can be dismissed as flake.

## Acceptance

- [ ] The cause is identified rather than the symptom suppressed — a shared working directory, a shared environment variable, a port, or genuine parallel-execution interference
- [ ] Twenty consecutive full-suite runs pass on an unchanged tree
- [ ] If the cause is a test's own assumption, it is fixed rather than serialised; if it is genuine shared state, the sharing is removed
- [ ] Neither test is deleted or marked skip as the resolution

## Notes

Do not attribute this to the suite's memory use — that was measured and cleared. The
suite peaks around 2.8 GB and is not the cause.

Being able to trust the suite matters more than usual right now: `TOAST-0005` and
`TOAST-0006` move thousands of lines with "the suite passes unchanged" as their entire
safety argument. A flaky suite makes that argument worthless, so this is worth doing
**before** the split rather than after.
