## Problem

The .NET runtime ignores `SIGPIPE`, so its own writes to a closed pipe fail with `EPIPE` instead
of ending the process. An ignored signal stays ignored across `exec`, and `Process.Start` only
resets signals that have a handler. Every program TōSh starts therefore begins with `SIGPIPE`
ignored — unlike under bash, where it is at its default and ends the writer silently.

Measured 2026-09-25 on the Debug build:

```text
$ tosh --safe -c '/usr/bin/grep SigIgn /proc/self/status'
SigIgn: 0000000000001000          # bit 13: SIGPIPE
$ bash -c 'grep SigIgn /proc/self/status'
SigIgn: 0000000000000000
```

- `/usr/bin/yes | /usr/bin/head -3` prints `/usr/bin/yes: standard output: Broken pipe` and `yes`
  exits 1. Under bash it ends silently, killed by the signal (status 141).
- `/usr/bin/cat big | /usr/bin/false` prints `cat: write error: Broken pipe`.
- A background job running such a pipeline reports `failed`, because one of its programs exited
  non-zero.
- A Python script writing to a closed pipe raises `BrokenPipeError` rather than ending.

[`TOSH-0012`](TOSH-0012.md) made TōSh close a pipe whose reader has gone, so the writer is no
longer left blocked; what the writer does next is this item.

## What does not work

`PosixSignalRegistration.Create((PosixSignal)13, ctx => ctx.Cancel = true)` registers without
error and changes nothing: a child still reports `SigIgn: …1000`. Measured with a stand-alone
program on .NET 11 RC1.

## Options

- Launch programs through `env --default-signal=PIPE`, which resets the disposition before it
  execs the program. GNU coreutils 8.31 and later only; costs one extra `exec` per program.
- A launcher of TōSh's own using `posix_spawn` with `POSIX_SPAWN_SETSIGDEF`. This replaces
  `Process.Start` for external programs — pipes, environment, working directory and waiting —
  which is a large change for a proof of concept.
- Accept it, and say so in the documentation.

## Acceptance

- [ ] a program started by TōSh has `SIGPIPE` at its default disposition
- [ ] `/usr/bin/yes | /usr/bin/head -1` prints nothing on stderr, and `yes` ends with status 141
- [ ] TōSh itself still survives writing to a closed pipe
