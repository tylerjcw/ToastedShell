> Status as filed: Proposed

## Problem

Reverse/static operator hooks

## Acceptance

Give right operands correct behavior for noncommutative mixed-type operations.

## Closed — 2026-09-20, by work filed elsewhere

Both halves exist and are specified.

**The right operand is consulted.** `§Operator Overloading`'s resolution order says so: if the
left operand defines the method it is invoked, *otherwise* the right operand's is, and only then
do the built-in and CLR `op_*` rules apply. `TOAST-0051` added the CLR fallback on both sides.

**A right operand can tell it is one.** An operator method may declare a second parameter,
`true` when the instance is the right-hand operand, which is precisely what a non-commutative
operator needs:

```tosh
class M(a) {
    prop A = $a
    func -(other, reversed) { return (($reversed) ? (10 - $this.A) : ($this.A - 10)) }
}

10 - (new M(3))    # 7
```

Measured 2026-09-20 during a sweep of proposed items: that returns `7`, which is `10 - 3` rather
than `3 - 10`. The specification carries the same example under *Operand orientation*, and states
the compatibility rule — the two-argument form is offered first and the single-argument form
remains the fallback, so an operator written without the parameter keeps its behaviour exactly.

Nothing is left of the acceptance line. Closed rather than carried.
